# Move a basic root to a shared drive

A basic root lives in the assistant account's My Drive, and every member's AI signs in as that one account. Once the group has Google Workspace, this branch moves the root to **shared services mode** (rules → Vocabulary → Mode): the root folder into a shared drive, the Agora events onto a shared calendar, the mail to a Google Group, and every member onto their own Workspace account. Run it with the root's owner (the admin, for a team), in their own app. Nothing is lost: diary entries, documents, to-dos and future events all come along.

Explain the why in one or two plain sentences before starting: everyone keeps their own account and password, and any member can then change or tidy any file.

**Progress** is a `## Move to shared drive` section in `setup.md` (rules → File kinds → templates), one box per step below, ticked as each Done when holds; resuming, start at the first unticked box. **While it runs**, the old root and, after step 4, its copy both hold `org.md`: the steps below name each one by its folder id, which step 4 records in its box ("old root `<id>`"). Ask members to leave Agora alone from step 4 until step 5 is ticked.

The admin's clicks are the `rules` skill's `references/manual-setup.md`; "item 4, step N" means its step N.

## Steps

1. **The admin's setup.** Walk item 4, Once per root, steps 1–5, with a Workspace account for every member in Members who uses the root (not the assistant account: it isn't a member, and it retires in step 9). Done when the admin has done steps 1–5 and you hold the shared drive's URL, the Calendar ID, who created the calendar, and the group's address (as `setup` → shared-services.md → 2a, steps 3–5, takes them).
2. **Hand-over from the assistant account.** Still connected as the assistant account:
   1. Share the root folder yourself through the Drive connector with the owner's Workspace account, as **Editor**, and read the permissions back until they list it.
   2. Click steps for whoever is signed in to Google Calendar as the assistant account: **Settings** → under "Settings for my calendars", the assistant account's name → **Share with specific people or groups** → **Add people and groups** → the owner's Workspace account, **See all event details** → **Send**.

   A solo root already on the owner's own Workspace account: nothing to hand over; tick this box and step 3 "(already)". Done when the folder's permissions list the owner's Workspace account as editor and the owner has the calendar invitation.
3. **Reconnect as the Workspace account.** The owner disconnects Google Drive and Google Calendar (and Gmail, when email is on) and connects them again as their Workspace account (prerequisites item 3, shared services), then accepts the calendar invitation from step 2. Done when item 3's shared services Who, Drive (at `drive_id`) and Calendar checks pass, and the calendar list shows the assistant account's calendar.
4. **Root in the shared drive.** List every folder and file under the root, with each one's owners. Before you start, the `landing/` folder must be empty (file what is there with the `file-document` skill), since filing names a document by its Drive creation time, which a copy resets.
   - **Move**, when the connected account owns every file and folder under the root (a solo root on the owner's Workspace account, typically): update the root folder's parent to `drive_id`. The folder keeps its id. Refused (Google lets only some roles move folders into a shared drive, and a connector may not re-parent across drives): copy instead.
   - **Copy**, otherwise: create a folder with the root's name in the shared drive (parent `drive_id`), then rebuild every subfolder under it by name, level by level, and copy every file into its new folder under the same name. A Markdown file may instead be downloaded and created again (rules → Working with Drive). Never trash or edit an original in this step.
   - **Count check**: list both trees, folder by folder; every folder in the new root lists the same file names as its original (moved: the same root, now under `drive_id`). A missing file is copied again until the check passes.

   Done when the count check passes and the box records the new root's id and, for a copy, "old root `<id>`".
5. **`org.md` and `setup.md`**, in the new root, written once each (rules → Replace):
   - `org.md` front-matter: `mode: shared-services`, `drive_id`, `root_id` (the new root's id), `calendar` (the Calendar ID), `calendar_owner` (the creator's slug) and `inbox` (the group's address). Keep `assistant_account` for the record.
   - Members: each member's Email becomes their Workspace account (ask the owner for any you don't hold), Personal calendar `domain free/busy` unless the member chooses more. The owner's Access row: Drive `content manager`, System calendar `can edit` (step 3's checks); every other member's Drive and System calendar `pending`, until they join.
   - `setup.md`: every Member section gets the shared services boxes (rules → File kinds → templates). The owner's Workspace account, In the shared drive and Shared calendar are ticked; every other member's boxes stay unticked, naming who does each.

   Done when the downloaded `org.md` shows every change above and `root_id` is the folder holding it (rules → Finding the root).
6. **Future events.** List the events on the old system calendar (`calendar` as it was, the assistant account's email) from now on whose title starts with `[<interest>/<instance>]`. Create each one on the new `calendar` with the same title, start and end (or all-day date), description, color and recurrence; a recurring series is created once, starting at its next occurrence. Leave the old calendar alone: delete nothing there. Done when every such event has exactly one copy on the new calendar (a series counted once). Tell the members they can hide the old calendar on their phones (Google Calendar → **Settings** → untick it).
7. **Forwarding** (email on; email off: tick "(email off)"). Click steps for whoever is signed in to Gmail as the assistant account: **Settings** (the gear) → **See all settings** → **Forwarding and POP/IMAP** → **Add a forwarding address** → the group's address → **Next** → **Proceed** → **OK**. The confirmation code arrives in the group, so in every member's inbox: enter it in the same tab → **Verify**. Then choose **Forward a copy of incoming mail to** the group, **keep Gmail's copy in the Inbox** → **Save Changes**. Add the old address to the Mail from cell of the member running the move (rules → Replace), so mail from it counts as member mail. Done when a test email sent to the old address from outside the organisation turns up in prerequisites item 7's shared services search, and `org.md` lists the old address in Mail from.
8. **Old root trashed** (copy only; a moved root: tick "(moved)"). Only once steps 4 and 5 are ticked. The connected account can't trash files the assistant account owns, so these are click steps for whoever is signed in to Google Drive as the assistant account: **My Drive** → right-click the old root folder → **Move to trash**. Done when a Drive search for `org.md` finds the new root only.
9. **Old account retired.** No connector signs in as the assistant account any more, and it isn't a member. Keep the account itself, with its password in the password manager: its forwarding (step 7) runs only while it exists. Each other member reconnects as their own Workspace account by running **Join** (it finds their Member section through their Email). Done when the owner knows the old account stays, unused, and each other member's Member section names Join as theirs to do.
10. **Linked repos.** List every `products/<instance>` with a Conventions row `managed by cruna-pm-github`: the instance is named after its repo. A developer reruns `pm-setup` from each of those repos, so its `.agora/pm.yml` names the new `drive_id` and `root_id`. No such instance: tick "(none)". Done when the owner has the list.

Done when every box is ticked, the new root passes SKILL.md step 7 (shared services mode), its calendar holds every future Agora event, and the owner has the linked-repo list. Then each other member runs **Join** in their own app.
